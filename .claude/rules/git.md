# Git — dynainfo-2

Repo on **GitHub**: `github.com/albansr/dynainfo-2`. Base branch: **`master`**. Active integration branch: **`dev`** (feature work branches off `dev`; `dev` → `master`).

## Branch naming

`tipo/descripcion_con_guiones_bajos` — separator is underscore `_`, never hyphen `-`.
If it references an issue, append `_#<number>` (exact GitHub issue number); with no issue, omit it entirely (never `_#00`).

Allowed types: `feature`, `refactor`, `docs`, `test`.

| Case | Bad ❌ | Good ✅ |
|------|--------|---------|
| Feature | `feat/add-roles` | `feature/add_dynaroles_model` |
| Refactor | `refactor/cleanup-pages` | `refactor/collapse_report_pages` |
| With issue | `feature/roles#12` | `feature/add_dynaroles_model_#12` |

## Commits (project rules — mandatory)

- **Never create commits unless the user explicitly asks.** The agent does not commit on its own.
- **Never push automatically** — after committing, stop and let the user decide when to push.
- **Never use the word "fix"** in commit messages — use **resolve / correct / improve** instead.
- **Never add** `Co-authored-by`, `Generated by`, or any Claude/AI attribution.
- Write messages from a **value-added perspective**: what improves and why it matters, not just what changed (mirror the existing history style, e.g. "Lead every product listing with item code and reference columns").
- Language: **English**. Imperative, concise title; optional body for the *why*.
- Before committing, **exclude** temporary/debug/test-output files (`*.tmp`, `debug_*`, `test_output*`).

## Pull requests

- **Base:** `feature/*` → **`dev`**. `dev` → `master`.
- **Small and focused:** one logical change per PR; keep the diff reviewable. Split if it grows large.
- Description: **what** changes, **why** (product value for features; technical rationale for refactors/infra), and **how to test**. Don't force a product narrative onto a refactor.
- Non-trivial PRs: add a short "key decisions" note for non-obvious choices; link the PRD/TDD if one exists.
- Self-review your own diff and run the checks green before requesting review.

## Never commit

Verify against `.gitignore` before committing:
- `api/.env` (and any `.env`), `api/ssl/` (certs).
- `node_modules/`, `dist/`, `.next/`, `coverage/`, `*.tsbuildinfo`.
- Only templates are committed (`.env.example` and similar).
